# Idris 速習

[前の章](./03-setup.md)で Idris はインストールできました。今度はそれを話せるようになる番です。これは言語リファレンスではありません——この先のすべての章を読むのに必要な最小限の Idris を、本書の他の部分と同じやり方で学びます。つまり、打ち込んで、返ってくるものを眺めるのです。

ターミナルを開き、`module Scratch` という 1 行だけを含む空のファイル `Scratch.idr` を作り、`idris2 Scratch.idr` で REPL に読み込みます。プロンプトが `Scratch> ` に変わります。以下の内容は、このファイルに書き足す(編集したら `:r` でリロード)か、このプロンプトに打ち込むかのどちらかです。ぜひ実際に手を動かしてください——この章は、指が参加すると 3 倍くらいよく効きます。

## 値には型があり、いつでも尋ねられる

`:t` コマンドは何の型でも教えてくれます。あなたの Idris 人生で最も多く発することになる質問です。

```
Scratch> :t 42
42 : Integer
Scratch> :t 3.14
3.14 : Double
Scratch> :t 'x'
fromChar 'x' : Char
```

`42 : Integer` は「42 は Integer 型を持つ」と読みます。(`fromChar` のノイズは、リテラルがオーバーロード可能であることを Idris が見せているだけです。無視して、コロンの後ろの型を読みましょう。)`Integer` は Python の int のような任意精度の整数。`Double` はおなじみの浮動小数点数。`Char` と `String` は見た目どおりです。

これから繰り返し登場する、初対面かもしれない型が 1 つあります。`Nat`——自然数、つまりゼロ以上の整数で、*負の数はありません*。Idris は、負の値がナンセンスになる場所すべてで `Nat` を使います。長さ、個数、インデックス。リテラルを特定の型に寄せたいときは `the` を使います。

```
Scratch> the Nat 3
3
Scratch> the Nat 3 - the Nat 5
Error: Can't find an implementation for Neg Nat.
```

3 引く 5 は自然数ではないので、Idris はこっそりラップアラウンドしたり負になったりする代わりに、コンパイル時に拒否します。これが設計哲学の最初のひと口です。実際に真であることを、型に言わせる。

## 関数

これを `Scratch.idr` に足します(そして REPL で `:r` してリロード)。

```idris
double : Integer -> Integer
double x = x + x
```

2 行、そしていつでもこの 2 行です。*型シグネチャ*が単独の行に——`double` は `Integer` を受け取り `Integer` を返す——続いて定義。`return` キーワードはありません。`=` の右辺が*そのまま*結果です。ここでの関数はまさに数学のそれだからです。同じ入力なら同じ出力、脇で起きることは何もなし。

```
Scratch> double 21
42
```

適用の構文に注目してください。`double 21`——引数を囲む括弧はありません。複数引数の関数は、矢印を重ねるだけです。標準ライブラリの `Nat` の足し算を見てみましょう。

```
Scratch> :t plus
Prelude.plus : Nat -> Nat -> Nat
```

`Nat -> Nat -> Nat` は「`Nat` を受け取り、さらに `Nat` を受け取り、`Nat` を返す」と読みます。矢印は読んだとおりの順に結合し、そこから愉快なことが転がり出てきます。2 引数の関数を*1 個の*引数に適用して、関数を返してもらえるのです。

```
Scratch> :t plus 1
plus 1 : Nat -> Nat
```

`plus 1` はれっきとした値——「1 を足す」関数——で、引き回すことも、後で適用することもできます。これは*カリー化(currying)*と呼ばれ(すべての関数は、実はこっそり 1 個ずつ引数を受け取っています)、適用構文に括弧がない理由でもあります。`plus 1 2` は実のところ `(plus 1) 2` です。部分適用は、本書の全編を通じて静かで有用な仕事をこなし続けます。

## パターンマッチと再帰

関数型言語は `if`/`while` の道具箱を、もっと良いものに置き換えます。*入力の形に対する場合分け*で関数を定義するのです。リストの長さを、ゼロから書いてみます。

```idris
length' : List a -> Nat
length' [] = 0
length' (first :: rest) = 1 + length' rest
```

等式が 2 本、リストの取りうる形ごとに 1 本ずつ。空リスト `[]` の長さはゼロ。先頭要素と残りから組み立てられたリスト(`::` は「コンス」と読みます)の長さは、残りの長さより 1 大きい。ループはありません——構造に対する再帰が歩いてくれます。`List a` の小文字の `a` は、この関数が*何の*リストにも働くという意味です。`a` は型変数です。(Rust 勢へ:`Vec<T>` の `T` です。山括弧がないだけ。)

```
Scratch> length' [10, 20, 30]
3
```

この形——コンストラクタごとに等式 1 本、データが再帰する場所で再帰——は、本書で単独最重要のパターンです。正規表現エンジンのコアは、まさにこれを 3 回やったものです。

## 自分のデータを作る

`data` キーワードは、値の作り方を列挙することで新しい型を導入します。

```idris
data Coin = Heads | Tails

flipCoin : Coin -> Coin
flipCoin Heads = Tails
flipCoin Tails = Heads
```

`Coin` はちょうど 2 つの値を持つ、真新しい型です。`Heads` と `Tails` は*コンストラクタ*と呼ばれ、パターンマッチはリストのときと同様に働きます。

```
Scratch> flipCoin Heads
Tails
```

コンストラクタはデータを運べますし、型はパラメータを取れます。「値があるか、何もないか」が欲しいとしましょう。

```idris
data Perhaps a = Nope | Yep a
```

`Perhaps Integer` は `Nope` か、あるいは `Yep 42`——本物の `Integer` を包んだ `Yep`——のどちらかです。そしてここで種明かし。これは自分で定義する必要がありませんでした。この言語で一番よく使われるデータ型として、`Maybe` という名前ですでに存在しているからです。

```
Scratch> :t Just
Prelude.Just : ty -> Maybe ty
```

`Maybe a` は `Nothing` か `Just x` のどちらか——そして、Idris が `null` の代わりに持っているものです。詳しくはすぐ後で。

## リストと、3 つの主力

リストリテラルと `::` はもう見ました。実は同じものです。

```
Scratch> 1 :: 2 :: 3 :: []
[1, 2, 3]
```

他の言語ならループを書くようなリスト仕事のほとんどは、3 つの関数がこなします。`map` は各要素に関数を適用し、`filter` はテストに合格した要素を残し、`foldr` は全要素を演算子で束ねます。

```
Scratch> map (* 2) [1, 2, 3]
[2, 4, 6]
Scratch> filter (> 10) [4, 25, 7, 90]
[25, 90]
Scratch> foldr (+) 0 [1, 2, 3, 4]
10
```

`(* 2)` や `(> 10)` は*演算子セクション*——またしても部分適用、今度は演算子のそれです。`foldr (+) 0 [1, 2, 3, 4]` は `1 + (2 + (3 + (4 + 0)))` を計算します。すべてのコンスを `+` に、最後の `[]` を `0` に置き換えるのです。他の関数を引数に取る関数は*高階関数(higher-order function)*と呼ばれ、こうして振る舞いを受け渡すことこそが、関数型コードの日々の手触りです。

絶えず必要になる、文字列固有の事実を 1 つ。`String` は `List Char` ではありませんが、変換は 2 つの関数、`unpack` と `pack` で済みます。

```
Scratch> unpack "abc"
['a', 'b', 'c']
Scratch> pack ['f', 'u', 'n']
"fun"
```

私たちの正規表現エンジンは入力を 1 文字ずつ消費するので、`unpack` は本編の 1 ページ目から登場します。

## レコード、let、where

名前付きフィールドを持つデータには、位置で区別するコンストラクタよりレコードが向いています。

```idris
record Point where
  constructor MkPoint
  x : Double
  y : Double
```

`MkPoint 3 4` で 1 つ作れて、フィールドはドット構文 `p.x` で取り出せます——ええ、あなたがすでに知っているすべての言語と同じです。ローカルな名前は `let ... in` で導入します。

```idris
distance : Point -> Point -> Double
distance p q =
  let dx = p.x - q.x
      dy = p.y - q.y
  in sqrt (dx * dx + dy * dy)
```

```
Scratch> distance (MkPoint 0 0) (MkPoint 3 4)
5.0
```

もう 1 つの選択肢が `where` で、補助定義をメインの等式の*下に*ぶら下げます——同じ考えの読み順違いで、補助関数には自前の型シグネチャが付きます。

```idris
average : List Double -> Double
average xs = total' / count
  where
    total' : Double
    total' = foldr (+) 0 xs
    count : Double
    count = cast (length xs)
```

小さな中間値には `let` を、自前のシグネチャに値する名前付きヘルパーには `where` を。本書は両方使います。

## ホール:会話としてのプログラミング

Idris を書く体験を一変させる機能がこちらです。どこかに何が入るのか分からないとき、*そう言ってしまえばいい*のです。`?` で始まる名前で。

```idris
swap : (a, b) -> (b, a)
swap (first, second) = ?whats_this
```

これが*コンパイルを通ります*。ファイルはロードされ、ホールを尋問できるようになります。

```
Scratch> :t whats_this
 0 b : Type
 0 a : Type
   first : a
   second : b
------------------------------
whats_this : (b, a)
```

探偵の捜査ボードのつもりで読んでください。線の下があなたの負債——型 `(b, a)` の値——で、線の上が手持ちのすべて。型 `a` の `first` と、型 `b` の `second` です。(`0` は「型そのものは実行時には手に入らない」という意味ですが、今は気にしなくて大丈夫。)ゴールと持ち物が並べば、定義はひとりでに書き上がります。

```idris
swap : (a, b) -> (b, a)
swap (first, second) = (second, first)
```

これがワークフローです。型シグネチャを書き、右辺にホールを置き、コンパイラに状況を尋ね、絞り込み、繰り返す。解の形をスケッチして、*型チェッカーを協力者にして*空欄を埋めていく——すべて書き上げてから口論するのではなく。後の章でコードが完成形のまま現れるように見えたら、それは実際にはこう書かれたのです。シグネチャが先、真ん中にホール。(編集注:idris2-lsp なら、ホールにホバーするだけで同じレポートがインラインに表示されます。)

## null の代わりの Maybe

答えがないかもしれないとき、Idris はどうするのでしょう?型でそう言うのです。「文字列の最初の文字」——空文字列で壊れるあれ——がこちら。

```idris
firstChar : String -> Maybe Char
firstChar str =
  case unpack str of
    []     => Nothing
    c :: _ => Just c
```

(`case ... of` は式の途中でのパターンマッチ。`_` は「何でもいい」のワイルドカードです。)

```
Scratch> firstChar "idris"
Just 'i'
Scratch> firstChar ""
Nothing
```

戻り値の型 `Maybe Char` は誠実な契約です。`Char` は手に入らないかもしれない——そしてコンパイラは、すべての呼び出し側に、値へ触れる前に `Nothing` のケースを処理させます。null が存在しないので、「null チェックを忘れた」も存在しません。10 億ドルの過ちは、ここでは修正されたのではなく——そもそも表現不可能なのです。

## インターフェースを、ちらりと

コインを 2 枚、比べてみましょう。

```
Scratch> Heads == Heads
Error: Can't find an implementation for Eq Coin.
```

`==` は組み込みの魔法ではありません——`Eq` という*インターフェース*に属していて、私たちの `Coin` 型はまだ入会していないのです。入会手続きはこんな見た目です。

```idris
Eq Coin where
  Heads == Heads = True
  Tails == Tails = True
  _     == _     = False
```

```
Scratch> Heads == Heads
True
```

インターフェースは能力に名前を付け(`Eq` は「`==` で比較できる」、`Show` は「`show` で `String` として表示できる」)、実装がそれを 1 つの型に対して提供します。(Haskeller へ:これは型クラスです。Rustacean へ:トレイトです。)後の章のシグネチャに `Show a => Eq a => ...` のような制約が現れたら、それは「任意の型 `a`、ただし表示と比較ができること」という意味です——私たちのテストハーネスが、まさに次の章でこれをやります。インターフェースにはずっと後で専用の章([インターフェースと 2 つのモノイド](./16-interfaces.md))が待っていますが、今は見分けられれば十分です。

## 全域性:誠実さを要求するコンパイラ

この行を `Scratch.idr` の先頭近く、`module` の行のすぐ後に足してください——正規表現エンジンのコアモジュールはすべてこれを携えています。

```idris
%default total
```

これは、すべての関数が*全域(total)*であること——起こりうるすべての入力に対して定義され、必ず完了することが保証されている——の検査を Idris に頼みます。全域関数は、算術と同じように信頼できる関数です。何を渡しても、答えが返ってくる。必ず。

チェッカーは実際のところ何を捕まえるのでしょう?2 つです。まずケースの抜け。`length'` から `[]` の等式を消すと、ファイルはコンパイルを通らなくなります。呼び出し側が空リストを渡してくるかもしれないのに、あなたは答えを持っていないからです。もう 1 つは怪しい再帰——これを `Bad.idr` というファイルに置いて、`idris2 --check Bad.idr` を試してください。

```idris
module Bad

%default total

countdown : Nat -> List Nat
countdown n = n :: countdown (n `minus` 1)
```

```
Error: countdown is not total, possibly not terminating due to recursive path Bad.countdown

Bad:5:1--5:28
 1 | module Bad
 2 |
 3 | %default total
 4 |
 5 | countdown : Nat -> List Nat
     ^^^^^^^^^^^^^^^^^^^^^^^^^^^
```

チェッカーは、何らかの引数が基底ケースへ向かって目に見えて縮んでいく再帰なら受け入れます——`rest` の上で再帰する `length'` は問題なし——が、`countdown` は止まることを証明できません(`minus` はゼロで底を打ってそこに居座るので、`countdown 0` は `countdown 0` を永遠に呼び続けます)。このエラーは、コンパイラが無限ループを*実行前に*捕まえた瞬間です。

Idris は 3 段階の誠実さレベルを、キーワードで区別します。`total` な関数はすべての入力をカバーし、そのすべてで停止します——金字塔であり、`%default total` が要求するものです。`covering` な関数は、すべての入力が*どれかの*等式にマッチすることは約束しますが、停止は約束しません——サーバーのループや、停止性をチェッカーが見通せないコードにとっての、誠実なラベルです。`partial` な関数は何も約束しません——一部の入力でクラッシュするかもしれず、その使用箇所のひとつひとつが、プログラムの死にうる場所です。Idris はその言葉を口に出させることで、恥が見えるようにしています。本書で書くものはほぼすべて `total` で、その事実は[テストが定理になる](./18-proofs.md)で、静かに構造を支える柱になります。全域関数とは、型チェッカーが*推論できる*関数なのです。

> [!NOTE]
> 全域性が言語機能であることの愉快な帰結:`total` は*予約語*です。変数に `total` と名付けようとすると、パーサに `Keyword 'total' is not a valid start to a declaration` と止められます。先ほどの `average` がヘルパーを `total'` と呼んでいたのはこのためで(末尾のプライムは伝統的な回避術です)、次の章で作るテストハーネスが合格数を `passedCount` という変数で数えるのも同じ理由です——そのソースにはこんなコメントが残っています。"Fun fact: the summary variable is called `passedCount` because `total` — the obvious name — is a reserved keyword in Idris!"

## 5 行の IO

環境構築の章で見たとおり、`putStrLn "hello"` はアクションの*記述*であって、実行されたアクションではありません。記述には型があります——`IO ()`、「実行されると、特に面白いものは生まないアクション」です。そしてコンパイルされたプログラムは、`main` という名前に束縛された記述を実行します。複数のアクションは `do` で順に並べます。

```idris
module Main

main : IO ()
main = do
  putStrLn "hello from Idris"
  putStrLn (show (2 + 2))
```

`Hello.idr` として保存して、コンパイルし、実行。

```sh
$ idris2 Hello.idr -o hello
$ ./build/exec/hello
hello from Idris
4
```

`do` は「それから」と読んでください。これをやり、それからこれ。今のところは本当にこれで十分です——私たちのテストスイート全体に、`do` ブロックはちょうど 1 個しか登場しません。`do` にはもっと深い何かがあります(`IO` よりずっと多くのものに働きますし、ええ、これが例の「モ」で始まる言葉へ続く道です)が、本書はコードがそれを*必要とする*まで説明しません。その瞬間は[パーサコンビネータ](./13-parser-combinators.md)で訪れます。それまでは、`do` は「それから」。第 1 章の約束は守られています——ブリトーはなしです。

## まとめ

- `:t` は何の型でも教えてくれます。`Integer`、`Double`、`Char`、`String` は期待どおりで、数を数える場所には `Nat`(負なし)が現れます。
- 関数はシグネチャ 1 行と等式たち。適用は空白で、関数はカリー化されていて、部分適用(`plus 1`、`(* 2)`)は日々の通貨です。
- データ型はコンストラクタの列挙。関数はコンストラクタの形ごとに等式 1 本で定義され、再帰はデータの再帰に従います——エンジン全体が、このパターンから組み上がります。
- `map`、`filter`、`foldr` がほとんどのループを置き換えます。`unpack`/`pack` が `String` と `List Char` を相互変換し、レコードはドットアクセス付きの名前付きフィールドをくれて、`let` と `where` がローカルなものに名前を付けます。
- ホール(`?name`)は不完全なプログラムをコンパイルさせ、空欄に何が入るべきかを型チェッカーに尋ねさせてくれます——シグネチャが先、真ん中にホール。本書のコードはすべてそうやって書かれました。
- `Maybe` は null を誠実な型で置き換えます。`Eq` や `Show` のようなインターフェースは型ごとの能力に名前を付け、`%default total` は、すべての関数がすべての入力に答えて停止することをコンパイラに検証させます——そして `total` は予約語です。テストハーネスの `passedCount` 変数が、その証人です。
- `do` は `IO` アクションを順に並べ、今のところは「それから」の意味です。深い話は[パーサコンビネータ](./13-parser-combinators.md)までお預けです。

これで Idris が読めるようになりました——今度は書く番です。この先のすべての章が立つ道具、[TDD と小さなテストハーネス](./05-tdd.md)から始めましょう。
