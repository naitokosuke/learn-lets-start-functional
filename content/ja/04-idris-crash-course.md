# Idris速習

[前の章](./03-setup.md)でIdrisのインストールは済みました．今度はそれを話せるようになる番です．これは言語リファレンスではなく，この先のすべての章を読むのに必要な最小限のIdrisを，本書の他の部分と同じやり方で学びます．つまり，打ち込んで，返ってくるものを眺めるやり方です．

ターミナルを開いて，`module Scratch`という1行だけを含むファイル`Scratch.idr`を作り，`idris2 Scratch.idr`でREPLに読み込んでください．プロンプトが`Scratch> `に変わります．以下の内容は，このファイルに書き足す(編集したら`:r`でリロード)か，このプロンプトに打ち込むかのどちらかです．ぜひ実際に手を動かしてみてください．この章は，指が参加すると3倍くらいよく効きます．

## 値には型があり，いつでも尋ねられる

`:t`コマンドは何の型でも教えてくれます．Idrisを書いていて一番よく発することになる質問です．

```repl
Scratch> :t 42
42 : Integer
Scratch> :t 3.14
3.14 : Double
Scratch> :t 'x'
fromChar 'x' : Char
```

`42 : Integer`は「42はInteger型を持つ」と読みます．(`fromChar`のノイズは，リテラルがオーバーロード可能であることをIdrisが見せているだけです．無視して，コロンの後ろの型を読んでください．)`Integer`はPythonのintのような任意精度の整数，`Double`はおなじみの浮動小数点数，`Char`と`String`は見た目どおりです．

これから繰り返し登場する，初対面かもしれない型が1つあります．`Nat`，つまり自然数です．ゼロ以上の整数で，負の数はありません．Idrisは，負の値がナンセンスになる場所(長さ，個数，インデックスなど)すべてで`Nat`を使います．リテラルを特定の型に寄せたいときは`the`を使います．

```repl
Scratch> the Nat 3
3
Scratch> the Nat 3 - the Nat 5
Error: Can't find an implementation for Neg Nat.
```

3引く5は自然数ではないので，Idrisは裏でラップアラウンドしたり負になったりせず，コンパイル時に拒否します．これが設計哲学の最初のひと口です．実際に真であることを，型に言わせる．

## 関数

`Scratch.idr`にこれを足してください(足したらREPLで`:r`でリロードです)．

```idris
double : Integer -> Integer
double x = x + x
```

2行です．そして関数は常にこの2行です．型シグネチャが1行(`double`は`Integer`を受け取って`Integer`を返す)，続いて定義です．`return`キーワードはありません．`=`の右辺がそのまま結果です．ここでの関数はまさに数学の意味での関数で，同じ入力なら同じ出力，横で何かが起きたりもしないからです．

```repl
Scratch> double 21
42
```

適用の構文は`double 21`で，引数を囲む括弧はありません．複数引数の関数は矢印を重ねるだけです．標準ライブラリの`Nat`の足し算はこうなっています．

```repl
Scratch> :t plus
Prelude.plus : Nat -> Nat -> Nat
```

`Nat -> Nat -> Nat`は「`Nat`を受け取り，さらに`Nat`を受け取り，`Nat`を返す」と読みます．矢印は読んだとおりの順に結合していて，ここから楽しい性質が転がり出てきます．2引数の関数を1引数だけに適用して，関数を返してもらえるのです．

```repl
Scratch> :t plus 1
plus 1 : Nat -> Nat
```

`plus 1`は立派な値(1を足す関数)で，そのまま引き回すことも後で適用することもできます．これはカリー化(currying)と呼ばれます(すべての関数は実は1つずつ引数を受け取っている，という話です)．適用構文に括弧がないのもこれが理由で，`plus 1 2`は実際には`(plus 1) 2`です．部分適用は本書全体を通して，静かに有用な仕事をし続けます．

## パターンマッチと再帰

関数型言語は`if`/`while`の道具箱を，もっと良いものに置き換えます．入力の形に対する場合分けで関数を定義するのです．リストの長さをゼロから書くとこうなります．

```idris
length' : List a -> Nat
length' [] = 0
length' (first :: rest) = 1 + length' rest
```

等式が2本で，リストの形1つにつき1本です．空リスト`[]`の長さはゼロ．先頭要素と残りから組み立てられたリスト(`::`は「コンス」と読みます)の長さは，残りの長さより1大きい．ループはありません．構造に対する再帰が歩いてくれます．`List a`の小文字の`a`は，この関数が何でも入ったリストに使えることを意味します．`a`は型変数です．(Rust勢へ: `Vec<T>`の`T`から山括弧を取ったものです．)

```repl
Scratch> length' [10, 20, 30]
3
```

この形(コンストラクタ1つにつき等式1本，データが再帰するところで再帰)が，本書で一番大事なパターンです．正規表現エンジンのコアは，まさにこれを3回やります．

## 自分のデータを作る

`data`キーワードは，値の作り方を列挙して新しい型を導入します．

```idris
data Coin = Heads | Tails

flipCoin : Coin -> Coin
flipCoin Heads = Tails
flipCoin Tails = Heads
```

`Coin`はちょうど2つの値を持つ新品の型です．`Heads`と`Tails`はコンストラクタと呼ばれ，リストと同じようにパターンマッチできます．

```repl
Scratch> flipCoin Heads
Tails
```

コンストラクタはデータを持てますし，型はパラメータを取れます．「値があるか，何もないか」が欲しいとしましょう．

```idris
data Perhaps a = Nope | Yep a
```

`Perhaps Integer`は`Nope`か，`Yep 42`のどちらかです．`Yep`が本物の`Integer`を包んでいます．そしてここでネタばらしです．これは定義する必要がありませんでした．この言語で一番よく使われるデータ型が，`Maybe`という名前でまったく同じ形をしているからです．

```repl
Scratch> :t Just
Prelude.Just : ty -> Maybe ty
```

`Maybe a`は`Nothing`か`Just x`で，Idrisが`null`の代わりに持っているものです．詳しくはすぐ後で．

## リストと3つの主力関数

リストリテラルと`::`はもう見ました．この2つは同じものです．

```repl
Scratch> 1 :: 2 :: 3 :: []
[1, 2, 3]
```

他の言語ならループを書くようなリスト仕事の大半は，3つの関数で片付きます．`map`は各要素に関数を適用し，`filter`はテストに通った要素だけを残し，`foldr`は全要素を演算子でまとめます．

```repl
Scratch> map (* 2) [1, 2, 3]
[2, 4, 6]
Scratch> filter (> 10) [4, 25, 7, 90]
[25, 90]
Scratch> foldr (+) 0 [1, 2, 3, 4]
10
```

`(* 2)`や`(> 10)`は演算子セクションです．またもや部分適用で，今度は演算子の部分適用です．`foldr (+) 0 [1, 2, 3, 4]`は`1 + (2 + (3 + (4 + 0)))`を計算します．すべてのコンスを`+`に，最後の`[]`を`0`に置き換える，という感じです．関数を引数に取る関数は高階関数と呼ばれ，こうやって振る舞いを引き回すのが関数型コードの日常の手触りです．

文字列について，この先ずっと必要になる事実をひとつ．`String`は`List Char`ではありませんが，変換は`unpack`と`pack`の2つの関数で済みます．

```repl
Scratch> unpack "abc"
['a', 'b', 'c']
Scratch> pack ['f', 'u', 'n']
"fun"
```

正規表現エンジンは入力を1文字ずつ消費するので，`unpack`は本編の1ページ目から登場します．

## レコード，let，where

名前付きフィールドを持つデータには，位置引数のコンストラクタよりレコードが向いています．

```idris
record Point where
  constructor MkPoint
  x : Double
  y : Double
```

`MkPoint 3 4`で作れて，フィールドは`p.x`のようなドット構文で取り出せます．すでに知っている言語たちと同じですね．ローカルな名前は`let ... in`で導入します．

```idris
distance : Point -> Point -> Double
distance p q =
  let dx = p.x - q.x
      dy = p.y - q.y
  in sqrt (dx * dx + dy * dy)
```

```repl
Scratch> distance (MkPoint 0 0) (MkPoint 3 4)
5.0
```

もうひとつの選択肢が`where`で，こちらはヘルパー定義をメインの等式の下にぶら下げます．考え方は同じで読む順番が違うだけですが，ヘルパーに自分の型シグネチャを持たせられます．

```idris
average : List Double -> Double
average xs = total' / count
  where
    total' : Double
    total' = foldr (+) 0 xs
    count : Double
    count = cast (length xs)
```

小さな中間値には`let`，シグネチャを与える価値のある名前付きヘルパーには`where`です．本書では両方使います．

## ホール:会話としてのプログラミング

Idrisを書く感覚を一変させる機能がこれです．どこかに何が入るのか分からないときは，`?`で始まる名前でそう言ってしまえばよいのです．

```idris
swap : (a, b) -> (b, a)
swap (first, second) = ?whats_this
```

これがコンパイルされます．ファイルもロードされます．そしてホールに問い合わせができます．

```repl
Scratch> :t whats_this
 0 b : Type
 0 a : Type
   first : a
   second : b
------------------------------
whats_this : (b, a)
```

刑事の捜査ボードのように読んでください．線の下が支払うべきもの(型`(b, a)`の値)で，線の上が手持ちの全部です．型`a`の`first`と，型`b`の`second`がありますね．(`0`は型そのものが実行時には使えないという意味ですが，いまは無視してください．)ゴールと手持ちの一覧が並べば，定義はほとんど勝手に書き上がります．

```idris
swap : (a, b) -> (b, a)
swap (first, second) = (second, first)
```

これがワークフローです．型シグネチャを書き，右辺にホールを置き，コンパイラに状況を尋ね，少し埋めて，繰り返す．全部書いてから型チェッカーと口論するのではなく，解の形をスケッチして，型チェッカーを相棒に空欄を埋めていく感じです．後の章でコードが完成形のままポンと現れるように見えたら，実際にはこう書かれたのだと思ってください．シグネチャが先，ホールが真ん中です．(ちなみに，idris2-lspならホールにホバーするだけで同じレポートがインラインに表示されます．)

## nullの代わりのMaybe

答えがないかもしれないとき，Idrisはどうするのでしょうか?型でそう言います．空文字列で壊れる「文字列の最初の文字」はこうなります．

```idris
firstChar : String -> Maybe Char
firstChar str =
  case unpack str of
    []     => Nothing
    c :: _ => Just c
```

(`case ... of`は式の途中でのパターンマッチです．`_`は「気にしない」のワイルドカードです．)

```repl
Scratch> firstChar "idris"
Just 'i'
Scratch> firstChar ""
Nothing
```

戻り値の型`Maybe Char`は誠実な契約です．`Char`が得られないかもしれないと明言していて，コンパイラはすべての呼び出し側に，値へ触る前に`Nothing`の場合を処理させます．nullが存在しないので，「nullチェックを忘れた」も存在しません．10億ドルの過ちは，ここでは修正されたのではなく表現不可能になっています．

## インターフェースをちら見

コインを2枚比べてみてください．

```repl
Scratch> Heads == Heads
Error: Can't find an implementation for Eq Coin.
```

`==`は組み込みの魔法ではありません．`Eq`というインターフェースに属していて，`Coin`型はまだそこに加入していないのです．加入はこう書きます．

```idris
Eq Coin where
  Heads == Heads = True
  Tails == Tails = True
  _     == _     = False
```

```repl
Scratch> Heads == Heads
True
```

インターフェースは能力に名前を付けます(`Eq`は「`==`で比較できる」，`Show`は「`show`で`String`にできる」)．そして実装が，それをひとつの型に対して提供します．(Haskell勢へ:型クラスのことです．Rust勢へ:トレイトです．)後の章でシグネチャに`Show a => Eq a => ...`のような制約が出てきたら，それは「表示できて比較できる限り，どんな型`a`でも」と言っています．次の章のテストハーネスがまさにこれをやります．インターフェースにはずっと後で専用の章([インターフェースと2つのモノイド](./16-interfaces.md))がありますが，いまは見分けられれば十分です．

## 全域性:誠実さを要求するコンパイラ

`Scratch.idr`の先頭近く，`module`行のすぐ後にこの行を足してください(正規表現エンジンのコアモジュールはすべてこれを付けています)．

```idris
%default total
```

これはIdrisに，すべての関数が全域(total)であること，つまり起こりうるすべての入力に対して定義されていて，必ず終わることの検査を頼む指示です．全域な関数は算術のように信頼できます．何を渡しても，答えが返る，いつでも．

チェッカーが実際に捕まえるものは2つです．まずケースの漏れ．`length'`から`[]`の等式を消すと，ファイルはコンパイルできなくなります．呼び出し側が空リストを渡してきたら答えがないからです．そして怪しい再帰．これを`Bad.idr`というファイルに置いて，`idris2 --check Bad.idr`を試してみてください．

```idris
module Bad

%default total

countdown : Nat -> List Nat
countdown n = n :: countdown (n `minus` 1)
```

```
Error: countdown is not total, possibly not terminating due to recursive path Bad.countdown

Bad:5:1--5:28
 1 | module Bad
 2 |
 3 | %default total
 4 |
 5 | countdown : Nat -> List Nat
     ^^^^^^^^^^^^^^^^^^^^^^^^^^^
```

チェッカーは，どれかの引数が基底ケースへ向かって目に見えて縮んでいく再帰は受け入れます(`rest`で再帰する`length'`はOKです)．しかし`countdown`は止まることを証明できません(`minus`はゼロで底を打った後もゼロのままなので，`countdown 0`は`countdown 0`を永遠に呼びます)．このエラーは，実行する前の無限ループをコンパイラが捕まえてくれた，ということです．

Idrisは3段階の誠実さレベルをキーワードで区別します．`total`な関数はすべての入力をカバーし，そのすべてで停止します．これがゴールドスタンダードで，`%default total`が要求するものです．`covering`な関数は，すべての入力がどれかの等式にマッチすることは約束しますが，停止は約束しません．サーバのループや，停止をチェッカーが見通せないコードに付ける誠実なラベルです．`partial`な関数は何も約束しません(入力によってはクラッシュしうるということです)．その使用箇所はすべてプログラムが死にうる場所で，Idrisはこの単語をわざわざ書かせることで，恥が見えるようにしています．本書で書くものはほぼすべて`total`で，この事実は[テストが定理になる](./18-proofs.md)で静かに効いてきます．全域な関数は，型チェッカーが推論できる関数だからです．

> [!NOTE]
> 全域性が言語機能であることの愉快な帰結として，`total`は予約語です．変数に`total`と名付けようとすると，パーサに`Keyword 'total' is not a valid start to a declaration`と止められます．先ほどの`average`がヘルパーを`total'`と呼んでいたのはこのためですし(末尾のプライムは伝統的な回避術です)，次の章で作るテストハーネスが合格数を`passedCount`という変数で数えるのも同じ理由です．ソースのdocコメントにもちゃんと書いてあります．一番自然な名前である`total`が予約語だったので`passedCount`になった，というFun factです．

## 5行のIO

環境構築の章で見たとおり，`putStrLn "hello"`はアクションの記述であって，実行されたアクションではありません．記述には型があります．`IO ()`，つまり「実行されると，特に面白くないものを生むアクション」です．そしてコンパイルされたプログラムは，`main`という名前に束縛された記述を実行します．複数のアクションは`do`で並べます．

```idris
module Main

main : IO ()
main = do
  putStrLn "hello from Idris"
  putStrLn (show (2 + 2))
```

`Hello.idr`として保存して，コンパイルして，実行します．

```sh
$ idris2 Hello.idr -o hello
$ ./build/exec/hello
hello from Idris
4
```

`do`は「それから」と読んでください．これをやって，それからこれ，です．いまのところ本当にこれだけで十分で，テストスイート全体でも`do`ブロックはちょうど1つしか出てきません．`do`にはもっと深い事情があるのですが(`IO`以外にも使えますし，そうです，これが例のモナドへ続く道です)，本書はコードがそれを必要とするまで説明しません．それは[パーサコンビネータ](./13-parser-combinators.md)で起きます．それまでは，`do`は「それから」です．1章の約束は守ります．ブリトーは出てきません．

## まとめ

- `:t`は何の型でも教えてくれます．`Integer`，`Double`，`Char`，`String`は期待どおりで，数えごとの場所には`Nat`(負なし)が現れます．
- 関数はシグネチャ1行と等式です．適用は空白で，関数はカリー化されていて，部分適用(`plus 1`や`(* 2)`)は日常の通貨です．
- データ型はコンストラクタの列挙です．関数はコンストラクタの形1つにつき等式1本で定義し，再帰はデータの再帰に従います．エンジン全体がこのパターンでできています．
- ループの大半は`map`，`filter`，`foldr`で置き換わります．`unpack`/`pack`が`String`と`List Char`を変換し，レコードはドットアクセス付きの名前付きフィールドを与え，`let`と`where`がローカルな名前を付けます．
- ホール(`?name`)を使うと，未完成のプログラムをコンパイルして，空欄に何が入るべきかを型チェッカーに尋ねられます．シグネチャが先，ホールが真ん中．本書のコードは全部こうやって書かれました．
- `Maybe`はnullを誠実な型で置き換えます．`Eq`や`Show`のようなインターフェースは型ごとの能力に名前を付けます．`%default total`は，すべての関数がすべての入力に答えて停止することをコンパイラに検証させます．そして`total`は予約語です(テストハーネスの`passedCount`変数が証人です)．
- `do`は`IO`アクションを並べます．いまのところ意味は「それから」だけで，深い話は[パーサコンビネータ](./13-parser-combinators.md)までお預けです．

これでIdrisが読めるようになりました．次は書く番です．後のすべての章が乗っかる道具，[TDDと小さなテストハーネス](./05-tdd.md)から始めましょう．
