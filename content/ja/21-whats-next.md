# この先へ

この本は，プログラミングはできるけれど関数型プログラミングは何も知らない，という状態から始まりました．最後に，持ち帰るものを数え上げて，道の続きを見ておきましょう．

## 作り上げたものを見てみましょう

空のディレクトリから始めた，本物の正規表現エンジンです．

- 正規表現*そのもの*である6コンストラクタのAST([正規表現はデータである](./06-regex-as-data.md))．[文字クラス](./11-character-classes.md)で記号的な文字集合へと一般化しました．
- ふたつの小さな関数[`nullable`](./07-nullable.md)と[微分](./08-derivatives.md)からなるマッチャ．入力をちょうど一度だけ歩く[1行のエンジン](./09-matches.md)に畳み込みました．
- あらゆる微分を小さく保つ[スマートコンストラクタ](./10-smart-constructors.md)．ベンチマークが取りこぼしを見つけた[対決](./19-the-race.md)で実戦鍛錬済みです．
- 便利さの層まるごと(`+`，`?`，`{n,m}`，文字列リテラル)を[ただの関数](./12-sugar.md)として．
- ゼロから作った[パーサコンビネータライブラリ](./13-parser-combinators.md)と，その上の[パターンパーサ](./14-pattern-syntax.md)，そして正直なエラー位置を持つ[公開API](./15-public-api.md)．
- テストによって証明可能にパーサを反転する[プリティプリンタ](./17-pretty-printing.md)と，正規表現の代数を公式のものにした[ふたつのモノイド](./16-interfaces.md)．
- `nullable`が健全かつ完全であることの[機械検証された証明](./18-proofs.md)．すべての正規表現について，コンパイル時に検証済みです．
- 自分の手で作ったバックトラック型ライバルとの[ベンチマーク](./19-the-race.md)と，エンジン全体をコンパイラのフロントエンドへと合成する[最長一致レキサ](./20-lexer.md)．

すべてテストファーストで，数百行のIdrisです．しかもコミット履歴が*そのまま*チュートリアルなので，どのステップでも再生できます．

```sh

cd lets-start-functional
git log --oneline --reverse
```




## 身についた関数型の考え方

**データが先．**本書でもっとも持ち運びのきくアイデアです．正規表現は文字列でも状態機械でもなく*木*であり，あらゆる能力(マッチ，印字，微分，字句解析)はそれを歩く関数です．[正規表現はデータである](./06-regex-as-data.md)で稼ぎ，以後のすべての章で現金化しました．問題がこんがらがって感じられたら，まず「データは何か?」と問うてみてください．

**純粋な芯と，IOの殻．**エンジンは決して印字せず，読み込まず，投げません．[テストハーネス](./05-tdd.md)でさえ`Spec`の値を純粋に保ち，`IO`は縁のひとつの関数に閉じ込めています．純粋性こそ，本書のすべての関数が「呼んで，値を比べる」だけで自明にテストできた理由です．

**網羅的なパターンマッチと全域性は，リファクタリングの保険．**[文字クラス](./11-character-classes.md)で`Lit`が`Sym CharSet`になったとき，コンパイラは，更新が必要なすべての関数の完全なTODOリストを作ってくれました．閉じたデータ型の上の全域関数とは，変更が触れる範囲を記憶ではなく機械が追跡してくれる，ということです．

**制御フローとしての高階関数．**`foldl (flip deriv)`はマッチャのメインループ*そのもの*です．パーサの`many`と`<|>`は反復と分岐*そのもの*です．[対決](./19-the-race.md)のバックトラッカーの継続`k`は，値になった「それから」です．他の言語がループと例外に手を伸ばすところで，関数を取る関数に手を伸ばせるようになったはずです．

**スマートコンストラクタと，代数的に考えること．**`cat`，`alt`，`star`は，項が組み立てられる唯一の場所で単位元(`Eps`，`Fail`)と吸収則を強制します．そして[インターフェースと2つのモノイド](./16-interfaces.md)は，これがはじめからモノイド構造だったことを明かしました．代数に名前を付けるのは飾りではありません．`anyOf []`は`Fail`でなければならないと，テストを書くより先に教えてくれたのはそれです．

**インターフェース(名前付き実装も含めて)．**契約(`Show`，`Eq`，`Semigroup`)，コンパイラが手渡す値としての実装，リクエストとしての制約．そして「どのモノイドが*その*モノイドか」へのIdrisらしい答えは，名前を付けて複数持ち，`@{...}`で選ぶ，でした．

**目に見える正格性．**Idrisは正格で，それが効いた場面がふたつありました．[パーサコンビネータ](./13-parser-combinators.md)では`recur`がパーサの自己参照を遅らせる必要があり，ベンチマークでは，時計が動き出す前に仕事が走らないよう`Lazy`が必要でした．遅延性は使えますが，*印付き*です．値がフェンスのどちら側にいるのか，いつでもわかります．

**正直さの注釈．**基準線としての`%default total`，パーサの再帰文法への意図的な`covering`，レキサにひとつだけの，コメントで正当化された`assert_smaller`．規律は「すべて全域であれ」ではなく，すべての例外が目に見え，局所的で，署名済みであることです．

**テストの延長線上にある証明．**[テストが定理になる](./18-proofs.md)は新しい活動を持ち込んだのではなく，すでにやっていた活動を延長しました．スペックは主張を例で検査し，証明は全入力で検査します．どちらも同じパターンマッチと再帰で動きます．依存型とは，テストスイートの野心を際限なく育てられるようにするもの，という感じです．

## 練習問題

おおよそ難易度順です．エンジンはもう手元にあるので，壊して，直してみてください．

1. **アンカー．**
   `^`と`$`をパターン構文に足しましょう．この本の`match`は文字列全体のマッチで，`contains`はパターンを`.*`で包みます．なので，まずここでアンカーが何を*意味すべきか*を考えてみてください．これはコーディングであると同じくらい，設計の練習です．
2. **最左検索．**
   `contains`はyesかnoを答えます．マッチが*どこ*にあるかを返す検索を書きましょう．レキサの`longest`(前進しながら最後の受理を覚える)が強力なヒントです．
3. **置換と分割．**
   位置が手に入れば，`replace : Regex -> String -> String -> String`と`split : Regex -> String -> List String`は充実した午後の仕事です．検索さえあれば，どちらも純粋なListの問題になります．
4. **キャプチャグループ．**
   難しく，そして値打ちがあります．各グループが*何に*マッチしたかを返そうとすると，タグ付き遷移へと押し出されます．産業用エンジンが線形性を手放さずにキャプチャ状態を線形時間の歩みに通す方法は，「PikeVM」や「tagged NFA」で検索してみてください．
5. **本物のDFA．**
   `deriv`をメモ化しましょう．正規化すれば，正規表現の微分の集合は有限になります([対決](./19-the-race.md)が身をもって教えてくれたとおりです)．なので，キャッシュすれば決定性オートマトンを前もって組めます．下のOwens–Reppy–Turonの論文が案内役です．
6. **Unicodeクラス．**
   この本の`CharSet`の範囲は，そのまま使えます．実物のカテゴリ表に裏打ちされた`\p{L}`のような構文を足して，「Unicode対応」のどれだけがコードではなくデータなのかを確かめてみてください．
7. **コンビネータのエラー位置．**
   この本の`compile`は，パースがどこで止まったかを報告します．コンビネータ自身に位置を追跡させて，どの`Parser`も「どこで，なぜ」失敗したのか言えるようにしましょう．これはパーサの型に触れます．抽象がどれだけ変更を閉じ込めてくれるかの，良い試金石です．
8. **ボス級: `deriv`の正しさを証明する．**
   `Matches (deriv c r) cs` iff `Matches r (c :: cs)`を述べ，両方向を証明しましょう．`Star`のケースは構造的帰納法だけでは足りません．ここで整礎再帰(well-founded recursion)が登場し，この本を卒業することになります．

## さあ，Haskellを読みに行こう

いま起きたことの種明かしをひとつ．Idrisを学んだことで，Haskell(関数型プログラミングの文献の多くが書かれている言語)を読めるようになっています．方言としては近いのです．本書がこう書いたところを

```idris
interface Semigroup ty where
  (<+>) : ty -> ty -> ty

[SeqSemigroup] Semigroup Regex where
  (<+>) = cat
```

Haskellのファイルはこう言います．

```
class Semigroup a where
  (<>) :: a -> a -> a

instance Semigroup Regex where
  (<>) = cat
```

コロンがひとつからふたつに，`interface`は`class`に，`implementation`は`instance`になります．そしてIdrisがふたつのモノイドを名前付きで持たせてくれたところでは，Haskellは値を単一フィールドの型に包んで，代数ごとに専用の型を与えます．

```
newtype Sum     = Sum     Int
newtype Product = Product Int

instance Semigroup Sum     where Sum a     <> Sum b     = Sum (a + b)
instance Semigroup Product where Product a <> Product b = Product (a * b)
```

対訳表はこちらです．

| Idris | Haskell |
|-------|---------|
| `interface` | `class` |
| `implementation`(無名) | `instance` |
| 名前付き実装，`@{...}` | newtypeラッパー(`Sum`，`Product`，...) |
| `x : Type` | `x :: *`(古い書き方)/ `x :: Type`(新しめのGHC) |
| 全域性チェッカ | 自力でがんばる |
| デフォルトで正格，`Lazy`はオプトイン | デフォルトで遅延，正格性はオプトイン |

敬意を払うべきは最後の行です．Haskellの遍在する遅延性には現実の帰結(スペースリーク，性能についての異なる考え方)があり，本書はそれを教えずに済みました．しかし，データ宣言，畳み込み，モノイド，型クラスは，もう全部読めます．Haskellの論文でもライブラリでも開いて，確かめてみてください．

## 読書リスト

- Janusz Brzozowski, **"Derivatives of Regular Expressions"**(Journal of the ACM, 1964)．この本の`Core`にあるすべての源流です．身をもって知ったとおり，あの正規化の修正も含めて，です．
- Scott Owens, John Reppy and Aaron Turon, **"Regular-expression derivatives re-examined"**(Journal of Functional Programming, 2009)．現代的な扱いです．文字クラス，正規化，DFAの構成，つまり本質的に本書のエンジンを，プロがやったものです．
- Russ Cox, **"Regular Expression Matching Can Be Simple And Fast"**とその続編([swtch.com/~rsc/regexp](https://swtch.com/~rsc/regexp/))．線形時間マッチングをひとつの運動にしたエッセイ群です．ベンチマークの`(a?){n}a{n}`は彼のものです．
- Edwin Brady, **"Type-Driven Development with Idris"**(Manning)．自然な次の一冊です．ここまで運んでくれた言語を，その作者が，テストの代わりに型が設計を導くやり方で教えてくれます．
- **Idris 2のドキュメント**([idris-lang.org](https://www.idris-lang.org/))．使ったすべてと，触れなかった多くのことのリファレンスです．
- そして**chibivue**([book.chibivue.land](https://book.chibivue.land/))へ敬意を込めて．小さく作ってテストファーストで進む本書の形式は，明らかにこの本に負っています．

## お別れ
